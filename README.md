# ピッタリ小銭パズル

Specifications.md に基づいたブラウザゲームです。ビルドやパッケージのインストールは不要です。

## 起動

`index.html` を Chrome / Safari などで開いてください。または、このフォルダで以下を実行し、http://localhost:8000 を開きます。

```sh
python3 -m http.server 8000
```

## 財布の初期設定を変更する

初期所持金（各硬貨・紙幣の枚数）・初期容量・容量ボーナスの調整値は、常に [wallet-config.js](wallet-config.js) を唯一の正とします。このファイルはゲームバランス調整のため随時変更するため、READMEには現在の設定値を転載しません。仕様書やテストの固定値と異なる場合も、初期設定は `wallet-config.js` を優先します。

`wallet-config.js` を編集して保存し、ブラウザを再読み込みしてください。ゲーム中の財布は引き継がず、新しい設定で開始します。「もう一度お買いもの」も読み込み済みの設定で初期化します。ファイルの変更を反映するには、リスタートではなくページの再読み込みが必要です。

- `coins`：各硬貨の初期枚数。すべて0以上の整数で指定します。
- `notes`：千円札・五千円札・一万円札の初期枚数。0以上の整数で指定します。`null`（引用符なし）で無制限、`0`で所持なしです。
- `maxCoinsCapacity`：硬貨枚数の上限。1以上の整数で、初期硬貨の合計枚数以上を指定します。紙幣は上限に含みません。

- `levelCapacityBonus`：レベルアップ1回で増える財布の容量（0以上の整数）。
- `exactCapacityBonus`：お釣り0円のピッタリ支払いで増える財布の容量（0以上の整数）。0なら容量ボーナスなしです。

硬貨・紙幣・容量ボーナスの設定キーは削除せず、値を変更してください。不正な値は画面に設定エラーを表示します。設定ファイルは直接HTMLを開く場合にも読み込めるJavaScript形式です。

有限の紙幣は投入すると減り、トレイから返すと戻ります。お釣りの紙幣も額面別に加算され、残り0枚の紙幣は選択できません。有限設定で資金が足りなくなった場合はページを再読み込みして初期状態に戻せます。

## 遊び方

- 小銭をタップ・上スワイプ、お札をタップして支払いトレイに投入。
- トレイ内のお金をタップすると1枚返却。「全返却」で投入を取り消せます。
- 価格以上を投入して「お会計」。お釣りは千円単位を紙幣で返し、1,000円未満の端数を最少枚数の硬貨で返します。紙幣は財布の小銭枚数に含めません。有限設定では紙幣の所持枚数に加算します。
- お釣りがある会計で小銭を減らすと、減らした枚数分のPTを獲得。レベルアップとピッタリ支払いで設定に応じた容量ボーナスを獲得。上限が増えなかった会計では容量−1。すべての増減を反映した容量が0以下になるか、硬貨枚数が容量を超えるとゲームオーバー。
- 「♪ OFF」で効果音をオンにできます。最高購入額はブラウザに保存します。

## 仕様の補足

初期財布・初期容量は `wallet-config.js` の設定から決まり、会計時の成長・ボーナス・摩耗によって容量が変化します。最初の商品はアイス、その後は6商品を一巡ごとに並べ替えて出品します。価格は初回・再開時を含め毎回リスクレベルに応じて生成します。容量アップ後も次の商品に進みます。戦利品は重力・バウンドのCSSアニメーションで、直近16点を表示します。結果のレシートには全購入品を掲載します。

画像は絵文字による仮イラストです。表示は端末によって異なります。Google Fonts が使えない場合もシステムフォントで動作します。ゲームデータは再読み込みでリセットされ、最高額のみ保持します。

## 検証

`tests/test.html` をブラウザで開くと、お釣りの最少枚数（1〜10,000円を動的計画法と照合）、返却、支払不足、容量アップ、容量境界、ゲームオーバー、リスク確率の切替境界、生成価格とリスクの一致、増減予測と実際の支払い結果、成長ポイント・摩耗・画面操作を検証します。

テストは専用の財布設定を使用し、ゲームバランス用の `wallet-config.js` から独立しています。実際の設定が初期状態に反映されることも別途検証します。Node.js がある環境では `node tests/run-logic.cjs` でロジック部分を実行できます。

- `game.js`: 描画から独立したゲームルール
- `app.js`: 操作、描画、サウンド、演出
- `style.css`: PC / スマホ向けレイアウト

## 成長・ポイントと財布の摩耗

- 上限が増えなかった会計では容量−1、上限拡張の必要PTは5で固定です。この2項目はゲームルールにハードコードし、設定ファイルからは変更できません。
- お釣りがある会計では、`max(0, 投入硬貨枚数 − お釣り硬貨枚数)` のPTを獲得します。
- 5PT以上になると1回だけレベルアップし、容量を `levelCapacityBonus` 分増やして保有PTを0にします。余剰PTの持ち越し・同一会計での複数レベルアップはありません。
- ピッタリ支払いはPTを獲得せず、容量を `exactCapacityBonus` 分増やします。容量ボーナスの有無にかかわらず、以前から保有していたPTを保持します。PTを0にするのは5PTの報酬を獲得したときだけです。
- PTまたはピッタリのボーナスで上限が増えた会計では摩耗しません。上限が増えなかった会計のみ摩耗します。処理順序は「ボーナス・PTリセット → 摩耗 → 容量超過判定」です。摩耗に下限はなく、容量10枚未満でも減少します。会計後の容量が0以下なら、硬貨が0枚でもゲームオーバーです。
- 財布上部の左半分に、小銭枚数・細い横並びの5段階インジケータ・上限枚数を表示します。2つの「〇枚」はインジケータ右端に揃え、右半分にお会計ボタンを配置します。小銭枚数のバーは表示しません。PTの数値ラベル・連続バー・摩耗カウントダウンはありません。読み上げ用には現在PTを提供します。
- 「〇枚へった！」の吹き出しはインジケータへ縮小移動して消え、獲得PTを反映します。5PT到達時は全点灯を短く表示してからリセットします。
- 会計後の上限が会計前より増えた場合は、上限の数字を拡大・バウンドさせます。動きを減らす設定では吹き出しをフェードにし、数字の拡大を抑止します。リスタートで進行中の演出を取り消します。

## 難易度と価格生成

購入完了数0〜2（1〜3品目）はレベル1〜5を60/30/10/0/0%、3〜9（4〜10品目）は10/30/40/20/0%、10以上（11品目〜）は5/15/30/35/15%で抽選します。

リスクは千円札だけで払える最小必要額 `ceil(価格 / 1000) × 1000` に対するお釣り枚数で決めます。0〜3枚 / 4〜6枚 / 7〜9枚 / 10〜12枚 / 13〜15枚が各レベルです。元の商品価格の千円単位部分を保ち、選択したレベルに合う1〜1,000円の端数候補から等確率で価格を生成します。購入済み商品の価格は固定です。

例示価格より枚数の定義を優先しています。999円は1枚でレベル1、1円は15枚でレベル5です。紙幣で返す分を除くため、お釣りの硬貨は最大15枚です。支払いに使わず財布に残った硬貨と、お釣りの硬貨の合計が、その時点の容量を超えるとパンクします。

支払いプレビューの増減は「お釣りの硬貨枚数 − トレイに投入した硬貨枚数」。投入前の財布を基準に、確定後の枚数と容量も表示します。金額不足・全返却・確定後は増減を表示しません。

例：9,030円に10,050円を出すと、お釣りは1,020円（紙幣1,000円＋10円玉2枚）。50円玉を1枚出しているため、小銭の純増は＋1枚です。

トレイのお金は1枚ずつ、角度や位置をずらして重ねて表示します。枚数が多い場合は全体を縮小して枠内に収め、スクロールバーは使いません。タップした1枚を返却できます。お会計後、お釣りの紙幣（一万円札・五千円札・千円札）と硬貨がトレイに並び、財布の各額面の位置へ移動します。お釣りがある場合は、獲得PTがあれば「2枚へった！」のようなポップアップを表示します。ピッタリ支払いでは獲得PTの有無にかかわらず「ぴったり！」を表示し、PT数のポップアップは出しません。ピッタリ会計ではポイントを加算せず、容量ボーナスと毎会計の摩耗を適用します。受け取り後に枚数表示・容量アップ・パンク演出を更新し、演出中は支払い操作を停止します。端末の「視差効果を減らす」設定では移動を短いフェードに置き換えます。

商品は右から現在位置へスライドインし、購入時に左へスライドアウトします。動きを減らす設定ではフェードに置き換えます。リスタート時は進行中の商品・PT・お釣り演出を取り消します。

紙幣ボタンは千円・五千円・一万円の順です。5,000円札も投入・1枚返却・全返却・有限枚数・お釣りに対応します。商品の補助見出しと番号、トレイ・財布の見出し、未投入時の指示文、LV表記、下部の説明文は表示しません。

## 画面サイズとセーフエリア

幅360pxを基準に、文字・アイコン・操作部のサイズをゲーム枠の幅から決めます。同じ幅なら、画面が縦長になっても要素のサイズは変わらず、商品などの配置間隔を広げます。ゲーム枠は最大幅480px、高さはゲーム枠の幅に比例する586〜650px相当の範囲で調整し、それ以上の縦長画面では中央配置と木目背景で余白を埋めます。

`viewport-fit=cover` と `env(safe-area-inset-bottom)` で、ホームバー・ノッチ用の余白をゲーム枠の外側に確保します。横画面や成長ゲージを含むゲーム枠が有効高さに収まらない場合はページをスクロールできます。

`tests/layout.html` で320×512、360×576、390×624、390×844、375×667、844×390を比較できます。iPhoneの実際のセーフエリア値はSafari実機で確認してください。
