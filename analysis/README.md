# 現行設定のシミュレーション

ゲーム本体は変更せず、wallet-config.js と game.js を直接読み込みます。

macOS（Python 3・OS標準JavaScriptCore）での再実行：

```sh
python3 analysis/run-simulation.py 10000 1000
python3 analysis/summarize.py
```

- simulation-report.html：統計表とヒストグラム
- simulation-results.csv：全試行
- simulation-results.json：設定・シード・ソースハッシュを含む結果
- summary.json：集計値

支払い方針は「生存 → 会計後の空き枚数 → 上限 → 残りPT → 過払いの少なさ」の順に優先します。支払い額ごとに投入硬貨枚数が最大になる組合せを動的計画法で求め、必要な千円札を補います。紙幣無制限設定専用です。候補選択時の予測と本体の予測が一致することを各会計で確認します。

現在の1会計で有利な支払いを選ぶ方針です。残す硬貨の種類の将来価値や、将来の商品価格を先読みする完全最適化は行いません。同額・同枚数の硬貨構成の同点は探索順で決まります。人間の実プレイ成績を推定するモデルではありません。

商品順はapp.jsのランダム比較sortによるバッグ生成を再現します。sortの乱数呼び出し順はJavaScriptエンジン依存です。画面演出が消費する乱数は省略しています。ゲームオーバーになった会計も購入数・総額に含め、上限ターンに達した生存試行は打ち切りとして区別します。

保存済みの集計・CSV・HTMLは旧設定（初期30枚、10PT＋1枚、ピッタリ時PTリセット）での結果です。現在の試作設定の結果ではありません。再実行すると結果ファイルを上書きします。
