# 4条件比較（2026-09-08）

再実行（macOS・Python 3・OS標準JavaScriptCore）：

```sh
python3 analysis/compare-balance.py 5000 1000
python3 analysis/comparison/report.py
```

ゲーム本体・設定ファイルは変更しません。現行コードを読み込み、別々のJavaScript実行コンテキストで次を適用します。

1. current：初期20枚・10PT＋3枚・ピッタリ＋2枚。ピッタリのPT加算なし、既存PT保持。
2. five_pt：初期20枚・5PT＋2枚・ピッタリ＋2枚。ピッタリのPT加算なし、既存PT保持。
3. exact_pt：初期20枚・10PT＋3枚・ピッタリ＋2枚。ピッタリでも減った硬貨枚数分のPTを加算。ピッタリ報酬とPT報酬は同時発生可能。

4. five_pt_one：初期20枚・5PT＋1枚・ピッタリ＋2枚。ピッタリのPT加算なし、既存PT保持。

すべて、PT報酬を受け取ったら余剰も含め0にリセット、1会計でのPT報酬は最大1回、上限アップ時は摩耗なしです。各試行は1,000ターンで打ち切ります。

乱数は20260908から連番、各条件で同じ商品列を利用します。画面演出の乱数消費は省略。ランダム比較sortはJavaScriptエンジン依存です。

支払い方針は手持ち硬貨の組合せを支払い額ごとに探索し、生存可能・会計後の空き枚数・上限・残りPT・過払いの少なさを優先します。各会計の容量・硬貨数予測を本体ロジックと照合し、各試行の容量収支を確認します。将来を先読みする最適解ではなく、人間プレイヤーの行動モデルでもありません。シミュレーション結果から楽しさ・実プレイ時間そのものは判断できません。

従来のanalysis/simulation-results.csv等は上書きせず、このフォルダに結果を保存します。

再実行時は設定・本体・支払い方針のソースハッシュ、試行数、打ち切りターン、報酬条件が一致する保存済み結果を再利用します。

比較後、ゲーム本体にはfive_pt_one（5PT＋1枚）を採用しました。保存済みレポートの「現状」は比較実施時の10PT＋3枚を指します。
